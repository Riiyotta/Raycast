# Raycast design/motion study clone

A local React 18 + Vite + Tailwind v3 study of raycast.com's layout, design tokens and motion. All copy and visuals are original placeholders. No Raycast copy, logos, screenshots, icons or illustrations are used.

```bash
npm install && npm run dev   # http://127.0.0.1:5174/
```

## Information architecture

| File | Edited by hand? |
|---|---|
| `ia.json` | **Yes.** This is the only IA file to edit. |
| `IA.md` | No. Generated by `node build.mjs`. |
| `matrix.csv` | No. Generated by `node build.mjs`. |

Re-run after any change to `ia.json`:

```bash
node validate.mjs && node build.mjs
```

### What the data shows (draft, 8 routes / 8 templates)

- **47 sections are defined, and only 11 appear on 2 or more pages.** Six of those 11 carry most of the reuse across the secondary pages: `feature.split`, `hero.page`, `faq.accordion`, `pricing.plans`, `feature.media-card-grid` and `feature.section-title`. Navbar and footer are on every route.
- **36 sections are single-use.** Ten of them are homepage-only and already built (shortcuts frame, time keyboard, extensions carousel, testimonials and so on). They should stay page-local until a second page needs one.
- **All 47 sections have an `implementedBy` component.** 27 live in `src/components/`. The 20 single-page pieces are small functions inside their page file in `src/pages/` (for example `Store.jsx > StoreToolbar`). Move one into `src/components/` only when a second page needs it.
- **The Windows page has the most page-local code.** 9 of its sections are page-specific, even though it reuses the shared split, media card, centered lead and FAQ components.

Sources: `CLONE_SPEC.md` (homepage) and `PAGES_SPEC.md` (secondary pages), both measured from the live site. Component names come from `src/components/`.
